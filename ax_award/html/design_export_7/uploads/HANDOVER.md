## 2. 파일 구조 — 무엇을 고치면 무엇이 바뀌나

```
ax_award/
  CLAUDE.md        ← 절대규칙 10개 + 서식 규격 + 페이지 예산 + 사실 카드. 모든 판단의 근거
  content.py       ← 본문 텍스트 상수. 머리말에 회차별 집행 기록이 쌓여 있다
  figures.py       ← 인포그래픽 PNG 를 PIL 로 직접 그린다 (그림 안 글자는 여기 하드코딩)
  build_docx.py    ← 조립. 규격 상수(여백·표너비·열너비·글자크기)는 건드리면 안 된다
  render_check.py  ← Word COM → PDF → PNG. 이전 렌더는 _prev/try{n}/ 으로 밀어 넣는다
  measure.py       ← 페이지별 실측. 눈대중 금지, 이 수치로 판단한다
  out/             ← 버전별 산출물. 절대 지우지 않는다
  out/fig/         ← 생성된 인포그래픽

.claude/workflows/ax-award-review.js   ← 29개 에이전트 오케스트레이션
```

### ⚠ 죽은 상수 함정 (제일 많이 헛손질한 곳)
`content.py` 의 아래 상수는 **어디서도 참조되지 않는다.** 고쳐도 렌더가 1픽셀도 안 변한다:
`ASIS_TOBE` `ASIS_SUM` `ACTION_LADDER` `AGENTS` `SPREAD_HEAD` `SPREAD_TABLE`
`EFFECT_FORMULA` `EFFECT_ROWS` `SENSITIVITY` `VERIFIER`

내용이 전부 `figures.py` 의 그림 안으로 옮겨갔기 때문이다. **그림 문구를 고치려면 `figures.py`
해당 함수 안의 하드코딩을 직접 고쳐야 한다.** 상수는 정본 문안 보관처로 남겨 뒀고,
각 상수 위 `DEAD` 주석에 대응 그림 함수명이 적혀 있다.


## 4. 에이전트 구성 (29개)

`.claude/workflows/ax-award-review.js` 한 파일에 들어 있다.
파일 맨 위 `ITER`(회차)·`VER`(검토 대상 버전) 두 줄만 매 회차 고친다.

```
┌ 데이터 확인 ─ haiku ×3 ────────────────────────────────────────┐
│  fit    분량 실측 — measure.py 돌려 어느 상수를 몇 줄 줄일지 지목  │
│  fact   사실 대조 — 정본에 없는 주장·수치, 규칙 위반 적발          │
│  brief  현황 브리핑 — 뒤 26개가 원본 파일을 다시 안 읽게 요약 생성  │
└────────────────────────────────────────────────────────────────┘
        ↓ (BRIEF 를 이후 전 단계 프롬프트에 주입 = 토큰 절약의 핵심)
┌ 심사 ─ opus·sonnet·fable 동시 ─┐   각자 100점 채점. 렌더 PNG 를 직접 열어본다
└───────────────────────────────┘
        ↓ 세 채점표 전문을 서로에게 전달
┌ 토론 ─ 3개 동시 ──────────────┐   반박·자기 철회·합의. 여기서 점수가 확정된다
└───────────────────────────────┘
┌ 디자인 ─ 3개 동시 → 토론 3개 ─┐   시각화 처방. visuals 최소 3건 필수
└───────────────────────────────┘
┌ 계획 ─ 초안 3개 → 합의 3개 ───┐   서로의 초안 전문을 보고 2라운드
└───────────────────────────────┘
┌ 마스터 ─ 3개 동시 → 토론 3개 ─┐   실행할 편집 하나로 좁힌다. net_cm ≤ 0 강제
└───────────────────────────────┘
        ↓
┌ 집행 ─ 1개 (회차마다 회전) ───┐   파일을 실제로 고치고 재빌드. 편집은 직렬화 필수
└───────────────────────────────┘
┌ 검수 ─ haiku ×1 ──────────────┐   페이지 수·금지어 grep·수치 대조. 판단 안 함
└───────────────────────────────┘
```

**모델 배분** — 상위 3개는 `opus` · `sonnet` · `fable`, 싼 모델은 `haiku`.
집행자만 회차마다 회전한다(`TOP[(iter-1) % 3]`). 편집을 3개가 동시에 하면 서로 덮어쓰므로
**논의는 3개 동시, 파일 편집은 하나**로 뒀다.

### 설계상 중요한 결정 4가지
1. **토큰** — 26개가 같은 파일을 각자 읽으면 회차당 수십만 토큰이 중복된다.
   haiku 가 만든 브리핑을 넘기고 "브리핑으로 판단이 서면 파일을 열지 마라"를 명시했다.
   렌더 PNG(vision, 제일 비쌈)는 **심사·디자인에만** 준다.
2. **토론은 진짜 교차여야 한다** — 초기에는 "다른 심사위원도 채점했다"고 말만 하고 내용을
   안 넘겨줬다. 이름만 토론이고 실제로는 자기 검토였다. 지금은 세 산출물 전문을 서로에게 준다.
3. **워크플로우는 반드시 `scriptPath` 로 실행한다.** 이름으로 실행하면 처음 등록된 사본이
   쓰여 수정이 반영되지 않고 `args` 도 안 닿는다(2·3회차에서 심사위원이 구버전을 채점했다).
4. **동시 실행 금지** — 두 회차가 겹치면 `content.py` 를 서로 덮어쓴다.

## 5. 절대규칙 (`ax_award/CLAUDE.md` §0 — 어기면 문서가 망가진다)

1. 서식 규격 변경 금지. `IIII. 경영효과` 를 `IV` 로 고치지 않는다
2. **쓸 수 있는 실측치는 §0-3 표에 있는 것뿐** — recall@10 0.500 / hit@1 1.000·0.957·0.962 /
   지연 1.29초 / 색인 5,291청크·103문서 / AMI 0.956 / ARI 0.860 / 노이즈 0.52% / 900 wafer.
   그 외 성능 퍼센트는 **더미로도 만들지 않는다**
   - hit@1 과 recall@10 을 한 문장에 나란히 놓지 않는다 (다른 시스템·다른 코퍼스)
   - AMI·ARI 를 "판정 정확도"로 부르지 않는다 (군집 품질 지표다)
   - 프로토타입 모델(bge-m3)을 본 과제 모델(Qwen3)로 바꿔 쓰지 않는다
3. **리소스 얘기 금지** — GPU 장수·VM·용량·FP8·"인프라"라는 단어 자체. 별건이다
4. **`I. 개요 > 분류` 두 칸(적용시점·횡전개 범위)은 더미 확정** — 수정 금지, 채점 제외
5. 모르는 값은 묻지 말고 더미로 채운다 (현재: 제조 AX 부문 / 제조기술센터 품질기술그룹 / 홍길동)
6. AI 말투 금지 — 정본 문장을 가져와 어절만 덜어낸다
7. 5장 초과 금지. 산출물 삭제 금지
8. **우선순위: 사용자 지시 > CLAUDE.md > 정본**

### 감점하면 안 되는 것 (데이터 상한 — 결함이 아니다)

- 4시간 가정 자체 — 문서가 이미 두 곳에서 가정임을 자백하고 민감도 4단으로 하방을 보였다
