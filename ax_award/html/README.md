## 원본과 달라진 점 3가지
1. **디자인 앱 껍데기 제거** — `<x-dc>` `<doc-page>` `<sc-if>`(심사 루브릭 배지, 원래 숨김)
   와 외부 css/js 링크를 걷어내고 `@page A4 / margin 0` 로 직접 고정했다.
2. **폰트 내장** — 본문이 `Noto Sans KR` 인데 사내 PC 에 없으면 Malgun Gothic 으로 떨어져
   자간이 달라지고 페이지가 넘친다. 문서에 쓰인 517자만 남긴 서브셋(94KB WOFF2)을
   base64 로 심었다. 가변 축(wght 100~900)을 살려 400/700/900 을 파일 하나로 덮는다.
3. **확대율 K=1.00** — 원본은 본문이 `10px`(=7.5pt)다. 예전 세대는 하단이 40% 넘게 비어
   `transform:scale(K)` 로 키웠지만, 소스 (6) 은 원저자가 내용을 계속 채워 **A4 를 이미 꽉 채운다**.
   실측 채움률 **81 / 80 / 96 / 99 / 93%**, K=1.01 부터 3페이지가 잘린다. 확대 여지가 없다.
   확대 장치(`--k`)는 그대로 두었으니 내용이 줄면 `measure.py` 로 다시 잡으면 된다.

## 남은 교정 (`patches.py`) — 도구 이름 정합
2026-08-09 에 넣었던 조사 흐름 교정(사고 원장 1순위 · meta 선별 후 하이브리드 · 이미지는
RAG DB 먼저 · 합류는 Router 증거 스택 · 도구 종료 후 Q/A 인계 · Router T=0 / Q/A T≈0.3)은
**소스 (6) 에서 원저자가 전부 반영**했다. 그래서 그 패치들은 뺐고, 지금 남은 건 정합 오류뿐이다.
대상 문자열이 없으면 **빌드가 실패한다** — 소스가 바뀐 걸 조용히 넘기지 않기 위해.

수치는 `ax_award/CLAUDE.md` §0-3 실측 목록 안에서만 썼고, §0-5(리소스 금지)에 따라
GPU·VM·용량은 한 글자도 넣지 않았다.

## 다시 만들기

```bash
python make_font.py            # 폰트 서브셋 (한 번만)
python measure.py 1.00 1.02 1.05   # K 후보별 채움률·넘침 실측
python build_html.py 1.00      # HTML 생성
python render.py               # PDF + 페이지 PNG
```
`measure.py` 는 "마지막 표를 바닥까지 늘리는" 규칙을 잠시 꺼서 실제 잉크 높이를 잰다 —
안 끄면 채움률이 항상 100% 로 나온다.

## 주의
- **채움률 100% 를 노려 K 를 올리지 말 것.** 소스 (6) 은 1.01 부터 3페이지가 잘린다.
  소스를 갈아끼울 때마다 `measure.py` 로 다시 잡아야 한다 — K 는 소스에 종속이다.
- 본문이 7.5pt 로 작은 편이다. 키우려면 3~5페이지(96~99%)에서 내용을 덜어
  1~2페이지(80%대) 로 옮겨야 한다 — 다만 II. Process / III. Tech 절 경계를 넘게 되니
  원저자가 디자인 앱에서 재배분하는 편이 낫다.
- 페이지 하단의 남는 공간은 마지막 표를 바닥까지 늘려 테두리 안쪽에 둔다
  (원본 docx 도 행 높이로 같은 방식으로 채웠다). 글자 크기는 5장 전부 같다.
- 본문 내용·수치는 원본 시안 그대로다. 사실 상한은
  `ax_award/CLAUDE.md` §0-3 과 디자인 프로젝트의 `notes/fig_inventory.md` 맨 아래를 따른다.
