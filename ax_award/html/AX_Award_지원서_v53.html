3. 병목 구간과 현업 문제
조사에 시간이 많이 든다 — 판정 한 건에 SPC, MES, YMS, EngrNote를 각 시스템에서 조회한 뒤 수동으로 대조한다. 판정 한 건에 최대 반나절이 소요된다, 계측: 건당 처리 시간
판단 기준이 사람마다 다르다 — 같은 trend를 봐도 베테랑과 신임의 결론이 다르다. 판정 기준이 시스템화되지 않고 개인 경험에 의존한다, 계측: 동일 현상 판정 일치율
야간, 주말 대응이 늦어진다 — 야간, 주말엔 변경점, 과거 사례를 아는 사람이 없어 Trend 수치만 정상 범위로 되돌리는 임시 대응이 발생한다, 계측: 발생→조사 착수 시각차
판단 근거가 기록으로 남지 않는다 — 근거가 문서로 안 남아 개인 판단으로 보정하고 지나간다. 담당자 변경 시 동일 조사를 반복한다, 계측: 담당 교체 후 재조사 건수

1. 왜 기존 자동화가 아니라 AI Agent인가
조사 순서를 사전에 고정하기 어렵다 — 다음에 볼 데이터가 직전 결과에 따라 달라진다. 고정 절차로 만들면 예외 분기가 지나치게 많아진다.
한 건의 판단에 여러 형태의 데이터가 필요하다 — 시계열, 이미지, 문서, 정형 DB. 데이터 유형별 전용 모델로 분석하고 LLM은 반환 결과를 종합한다.
출력은 단순 분류값이 아니라 근거가 포함된 판정서여야 한다 — 분류 모델은 Hold/Release 값만 반환한다. 판정은 결론보다 근거가 감사 대상이다.
고정 임계값만으로는 잡기 어렵다 — 임계값 이하에서 진행되는 완만한 shift는 규칙 알람으로 찾기 어렵다. 변화점 검정이 필요하다.
1-1. 기존 자동화 방식의 한계
사내 LLM API단독 적용 어려움질문을 넣으면 일반 지식으로 답할 뿐 — SPC, MES 조회, Map, SEM 판독, 변경점 대조 기능이 없다. 질문자가 제공한 정보 범위를 넘어 현장 근거를 자동 확보하지 못한다
사내 공용 RAG단독 적용 어려움문서를 단일 벡터 중심으로 검색하는 구조 — 설비 ID, 공정 약어가 임베딩만으로는 식별력이 낮아 검색 정확도가 낮고, 반도체 사전, 용어 병기, 메타데이터 필터 등 검색 제어 수단이 없다
BI, 대시보드단독 적용 어려움화면을 추가해도 시스템 간 대조와 판단, 조치는 사람의 업무로 남는다 — 대조, 판단, 조치는 여전히 사람 공수로 남는다
규칙 기반 SPC 알람활용규격과 규칙 기반이라 정해둔 임계만 잡는다 — 완만한 drift, 복합 이상은 통과. 상시 감지는 Trend Agent가 대신하고, SPC 알람은 이벤트 기반 자동 실행 트리거로만 쓴다
