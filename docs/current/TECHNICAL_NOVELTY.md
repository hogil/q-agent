# 기술 차별성과 검증할 기여

## 현재 평가

현재 구현은 새 학습 알고리즘보다 반도체 품질 조사에 맞춘 시스템 설계와
실행 규칙의 조합이다. 페르소나, 역할 분리, 필요 시 검색, Judge 재조회만으로
알고리즘 novelty를 주장하기는 어렵다. 이 문서는 대표 선행연구와의 제한된
비교이며 포괄적인 신규성 조사나 특허 판단이 아니다.

[ReAct](https://arxiv.org/abs/2210.03629)는 추론과 외부 행동을 결합한다.
[Self-RAG](https://arxiv.org/abs/2310.11511)는 필요에 따른 검색과 자기 검토를
다룬다. 따라서 'Tool을 선택한다', '검색이 필요 없으면 생략한다', '근거를
검토한다' 자체는 본 프로젝트 고유 기여가 아니다.

## 현재 구현에서 기여 후보가 되는 부분

| 기여 후보 | 구현 근거 | 아직 주장할 수 없는 것 |
|---|---|---|
| 요청별 데이터 의존성과 사고 범위 계약 | independent/incident 분리, 사고 scope 소유자·만료·후속 Tool 검사 | 자연어 분류의 정확도, 운영 ACL 완성 |
| 사고 테이블 수량과 관계 의미 보존 | 세대 배열 distinct 집계, 사고-Lot-Wafer 연결, 재고와 사고 영향 구분, 부분/충돌 상태 | 실데이터의 원인 규명 성능 |
| 검토 결과를 실행 가능한 계약으로 연결 | 미해결 issues의 pass 차단, 근거 ID/범위/출력 상태 검사 | 의미적 환각 완전 차단 |
| 변경 가능한 지시문의 재현성 | 역할별 Skill 조립, 릴리스 해시, 줄바꿈/경로 정규화, 회귀 | 모델 학습 기법의 신규성 |

가장 설득력 있는 연구 가설은 **선택적 조회와 사고 테이블 관계 제약을 함께 적용하면,
불필요한 DB 호출을 줄이면서 잘못된 사고 범위와 수량을 보고하는 오류도 줄일 수 있다**는 것이다.
현재는 가설이며 비교 실험으로 입증하지 않았다.

## 필요한 비교 실험

같은 모델·질문·도구·데이터·예산에서 다음 구성을 비교한다.

1. 단일 프롬프트 + 일반 Tool 선택.
2. Router/Judge/Answer 분리만 적용.
3. 모든 요청에 사고 DB 우선 조회.
4. 선택적 조회 + 사고 범위/관계/출력 형식 전체 적용.

DB 불필요 요청과 필수 요청을 별도로 분모에 둔다. 불필요 DB 호출률,
필수 DB 생략률, 사고 범위 혼합률, 수량 오류율, 근거 충족률, 과잉 거절률,
완료율, 지연/토큰을 보고한다. 범위 검증/수량 검사/Judge를 각각 제거한
ablation과 보류 질문 평가가 필요하다. 초기에는 합성 정답 집합으로 시작하고
실제 사내 자료 평가는 별도 승인된 환경에서 검증한다.

기존 234개 질문은 제한 문법 조회 회귀다. 그 통과율을 LLM 정확도나
선행연구 대비 우수성의 증거로 사용하지 않는다.
