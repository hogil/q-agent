# 실행 평가 및 Windows 재현성 개선

## 범위와 결론

2026-09-13, Windows / Python 3.13에서 실제 코드를 실행했다. 데이터는
저장소의 합성 fixture이며, 사내 DB나 LLM 서버를 호출하지 않았다.
현재 단계는 독립 조회 Tool과 Skill 컴파일러 데모다.

## 장점

- 사고 조회 후 발급한 범위와 사용자 일치를 검사하고, 복수 후보의
  Lot/Wafer 조회 전에 명시적 선택을 요구한다.
- 배열 원소 조회와 distinct 사고 집계를 분리하며, 세대별 수량을 임의 배분하지 않는다.
- 테이블/컬럼 매핑 교체, 읽기 전용 연결, 조회 실패와 0건 구분을 검증한다.
- Skill 릴리스 무결성, 역할별 로딩, 근거 없는 응답 계약 거부를 검사한다.

## 발견한 문제와 수정

1. Windows 경로 구분자 때문에 파일이 있어도 `RELEASE_FILE_SET_CHANGED`가 발생했다.
   릴리스 키와 프롬프트 출처를 POSIX 형식으로 통일했다.
2. Git checkout의 CRLF/LF 차이로 같은 텍스트의 해시가 달라졌다.
   텍스트 해시는 CRLF를 LF로 정규화하고 파일 순서와 UTF-8 읽기를 명시했다.
   실제 내용 변경은 계속 거부한다. 릴리스는 명시적으로 다시 freeze했다.
3. 테스트의 SQLite 연결이 닫히지 않아 Windows 임시 DB 정리가 실패했다.
   트랜잭션 처리와 별도로 `closing()`을 적용했다.

Skill 19개와 참조를 합한 파일 33개는 로컬과 Git에 있으며 릴리스 목록과 일치했다.
이번 변경은 Skill 지침 내용을 바꾸지 않는다.

## 실행 결과

| 검증 | 통과 |
|---|---:|
| Lot 데모 | 19/19 |
| 배열 데모 | 7/7 |
| Skill 및 줄바꿈 회귀 | 36/36 |
| 설정 | 31/31 |
| Wafer | 15/15 |
| 오타/동의어 및 선택 경계조건 | 25/25 |
| 작성된 프롬프트 계약 | 41/41 |

추가 통합 실험은 사고 128건, Lot 관계 640건, Wafer 관계 7,680건을
새 임시 DB에 생성해 기존 질문 234개를 실행했다. 결과는 **234/234 통과**,
생성과 조회를 합한 단일 실행 시간은 **27.212초**였다. 성능 개선 전후 비교나
부하 시험 수치는 아니다. 임시 DB와 전체 결과는 테스트 종료 시 정리된다.

저장소 루트에서 `python app/check_retrieval_corpus.py`로 재현한다.
기존 검증은 위 표에 대응하는 `app/demo.py`, `app/array_demo.py`,
`app/check_skills.py`, `app/check_config.py`, `app/check_wafers.py`,
`app/check_variants.py`, `app/check_prompt_contracts.py`를 실행한다.

## 남은 한계와 다음 실험

- 질문 corpus는 라벨이 있는 제한 문법이다. 자연어 LLM 정확도나 미지 질문의
  일반화 성능을 나타내지 않는다. 독립 작성한 보류 질문이 다음 평가 대상이다.
- Router/Judge/Answer 실호출, 운영 ACL, snapshot, Hybrid RAG, 이미지/Trend
  모델 및 승인 조치 연동은 여전히 미구현이다.
- 다음 단계는 조회 계층의 오류/범위 계약을 유지하면서 역할별 실호출을 연결하고,
  근거 누락 시 Router 재조회와 마지막 Answer 호출 순서를 통합 검증하는 것이다.

## 추가 경계조건 평가와 개선

기존 corpus와 별도로 작성한 테스트 4개는 수정 전에 모두 실패했다.
잘못된 선택값 4종의 subtest를 포함하면 실패 보고는 7건이다.

| 평가 입력 | 수정 전 | 수정 후 |
|---|---|---|
| 선택값 `[]`, `''`, `False`, `0` | 선택값을 무시하고 Wafer 조회까지 진행 | 기존 선택 검증에서 거부, 사고 우선 조회 이후 후속 조회 없음 |
| 동일 사고 ID 두 번 선택 | 결과 ID와 trace 건수가 중복 | 검증된 scope의 고유 ID와 건수를 사용 |
| 기준일 `2025-W01-1` | 실제 날짜가 2024-12-30인데 alias 만료로 판단 | ISO 날짜를 calendar 형식으로 정규화 후 유효기간 비교 |
| 명시적 빈 기준일 | 사전 기본 기준일로 대체하고 실행 | INVALID_REQUEST |

수정은 `terminology.py`와 `variant_query_demo.py`의 입력 처리에 한정했다.
Skill 내용과 사전은 변경하지 않았으며, 릴리스 해시는 명시적으로 갱신했다.
추가 사례 4/4와 전체 단위/계약 검증 174/174가 통과했다.
수정 후 기존 corpus도 234/234 통과했고, 생성과 조회 시간은 26.301초였다.
이 평가는 정확성 회귀이며 처리속도 개선이나 자연어 일반화의 증거가 아니다.

## Codex 앱 서버와의 구분

설치된 Codex CLI 0.154.0의 도움말에서 app-server, WebSocket 리스너와 인증
옵션을 확인했다. 원격 클라이언트 접속 검증은 수행하지 않았다.
Codex의 `skills/list`는 Codex가 발견한 Skill을 조회하며, Q-Agent의
`app/skills`는 현재 자체 컴파일러가 읽는다. 두 로딩 경로를 혼동하지 않는다.
관련 프로토콜은 [공식 문서](https://learn.chatgpt.com/docs/app-server)를 따른다.
