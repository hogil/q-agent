# 요청별 사고 DB 필요성

2026-09-13 사용자 요구에 따라 quality-demo-0.14에서 공통 우선 조회 규칙을
사고 의존 요청에만 한정했다. 근거는 현재 저장소 설계와 합성 계약 평가다.
사내 데이터 및 실제 LLM의 분류 정확도는 미검증이다.

| 요청 | request_scope | 사고 DB |
|---|---|---|
| 사고 검색, 영향 Lot/Wafer, 사고 통계, 특정 사고 원인/조치 | incident | 우선 조회 필요 |
| 제공한 문서만 요약, 제공된 정의 설명, 독립적인 일반 문서 검색 | independent | 호출 금지 |
| 일반 설명과 특정 사고의 사실을 함께 요구 | incident | 사고 관련 근거에 필요 |
| 범위가 미확정 | 기본 incident, 모호함 확인 | 독립 요청으로 임의 우회하지 않음 |

## 흐름

| 순서 | 사고 조사 | 사고와 독립적인 요청 |
|---|---|---|
| Router | 사고 조건/조회 계획 | 제공 근거만 사용하거나 independent Tool 계획 |
| 사고 DB | 조회 후 scope 발급 | 생략 |
| 필요한 Tool | 사고 scope 안에서 후속 조회 | 독립 문서/참조 조회만 |
| Judge | 사고 범위와 요구 충족 검토 | 요청에 필요한 근거 검토, 사고 미조회를 결함으로 세지 않음 |
| Answer | 사고 사실과 범위/한계 | 요청한 설명/요약, 사고 없음으로 표현하지 않음 |
| 최종 표시 | 조회 상태와 사고 범위 | 사고 범위 적용 대상 아님 |

Judge 재조회는 두 경로 모두 같은 Router로 돌아간다.

## 코드 계약과 구현 범위

`request_scope`는 신뢰할 호출 코드가 공급한다. Router 출력이나 문서 안의
동명 문자열로 바꾸지 않는다. 자연어에서 이 값을 결정하는 운영 분류기는
아직 없으며, 독립 분류의 정확도를 검증했다고 주장하지 않는다.

independent는 stage=independent, search_mode=none, filters={}를 요구한다.
Tool도 동일 단계로 등록돼야 한다. 사고 DB용 Tool의 단계를 모델이 바꿔도
검증기에서 거부한다. 사고 요청의 기존 scope/우선 조회 검사도 유지한다.

`app/plan_executor.py`는 전체 계획과 Adapter 존재를 확인한 뒤 호출한다.
DB를 자체 생성/연결하지 않는다. 범위 판정, 인증, Adapter 등록, Adapter별
인자/권한 검증은 호출 시스템의 책임이다. 완성된 LLM Orchestrator는 아니다.
