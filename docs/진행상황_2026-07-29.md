## 2-1. ⚠ 사고 — pgvector 가 제거된 채 빌드 실패 (복구 필요)

0.8.2 업그레이드를 시도하면서 **tarball 이 없는 상태로 절차를 실행**해 pgvector 가 완전히 빠졌다.

```
tar (child): v0.8.2.tar.gz: Cannot open: No such file or directory   ← 반입 파일이 아직 없음
make: *** No targets specified and no makefile found. Stop.          ← 그래서 빌드도 안 됨
Removing postgresql-16-pgvector (0.6.0-1) ...                        ← 그런데 apt 제거는 실행됨
ERROR: extension "vector" is not available
  DETAIL: Could not open extension control file
          "/usr/share/postgresql/16/extension/vector.control"
```

**원인**: 반입 절차의 `sudo apt remove postgresql-16-pgvector` 는 **소스 빌드가 성공한 뒤에만**
실행해야 하는데, tarball 이 없어 빌드가 실패했음에도 제거 단계가 그대로 돌았다.

**복구(즉시)**:
```bash
sudo apt install postgresql-16-pgvector          # 0.6.0 다시 설치
sudo -u postgres psql -d qagent -c "CREATE EXTENSION IF NOT EXISTS vector;"
sudo -u postgres psql -d qagent -c "SELECT extversion FROM pg_extension WHERE extname='vector';"
```

**세션에서 확정된 안전판 절차** — 두 가지를 고쳤다:
① `&&` 체인이라 앞 단계가 실패하면 뒤가 절대 실행되지 않음
② **`apt remove` 를 아예 뺐다** — 소스 설치가 같은 경로를 덮어쓰므로, 제거하면 **방금 빌드한 파일까지
   지워지는 함정**이 있다. 대신 `apt-mark hold` 로 apt 가 0.6 으로 되돌리지 못하게 잠근다.

```bash
# ★ 반입 완료 후에만 실행 — 파일 존재 확인부터
ls -lh v0.8.2.tar.gz \
  && tar xzf v0.8.2.tar.gz \
  && cd pgvector-0.8.2 \
  && make \
  && sudo make install \
  && sudo -u postgres psql -d qagent -c "ALTER EXTENSION vector UPDATE TO '0.8.2';" \
  && sudo -u postgres psql -d qagent -c "SELECT '[1,2,3]'::halfvec(3);" \
  && sudo apt-mark hold postgresql-16-pgvector      # apt 가 0.6 으로 되돌리지 못하게 잠금
```

**데이터 손상은 없다** — 아직 벡터 테이블을 만들기 전이라 DB 안 설정(`qagent` DB·확장 등록)은 그대로 살아 있다.
