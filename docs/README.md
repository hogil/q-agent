## 5. ⚠ 미해결 — 문서 간 충돌 1건 (pgvector 버전)

두 문서가 다른 버전을 말한다. **둘 다 실측이고 서로 틀리지 않았다 — 기계가 다르다.**

| 출처 | 기계 | 버전 | halfvec |
|---|---|---|---|
| `진행상황_2026-07-29.md` | **data01** (사내 apt) | **0.6.0** | 불가 |
| `INFRA_발급정보.md` §4 (2026-08-06) | **테스트 VM** | **0.8.1** | 가능 |

스키마를 `halfvec(1024)`로 확정한 근거는 테스트 VM 쪽이다. 그런데 **실서비스는 data01에서 돈다.**
data01의 사내 apt는 0.6.0까지만 줬고, 0.8.2 소스 빌드 시도는 tarball 없이 `apt remove`가 실행돼
확장이 통째로 빠지는 사고로 끝났다(`진행상황_2026-07-29.md` §2-1).

**확인할 것 하나**: 테스트 VM이 0.8.1을 어느 경로로 얻었는가 — 소스 빌드인가, 다른 apt 소스인가.
그 경로를 data01에 적용하기 전까지 **data01에서 `halfvec` 컬럼 생성이 성공한다고 가정하지 말 것.**
반입·재설치 시에는 `진행상황_2026-07-29.md` §2-1의 안전판 절차(`&&` 체인 + `apt remove` 대신 `apt-mark hold`)를 그대로 쓴다.
