## 직접 운영의 이점

- **스펙 상향**: 관리형 32c/128GB → data01 **64c/1TB** (벡터 인덱스 전량 메모리 상주 가능 — 관리형에선 불가)
- pgvector 버전 자유 선택 (0.7+ halfvec 로 색인 절반)
- shared_buffers 등 튜닝 자유, 월 748,153원 절감

## 직접 운영 체크리스트

- **HA**: data01(primary)→data02(standby) 스트리밍 복제 + 승격 절차.
  자동 failover 필요 시 Patroni (초기 수동 승격 가능)
- **백업**: pgBackRest/pg_basebackup — 일 풀백업은 VM DISK 백업(신청분), WAL 아카이브는 NAS.
  복구 리허설 분기 1회
- **패치**: 마이너 업데이트 직접 — 버전 고정(판정 재현성) 원칙과 충돌 없게 **월 4회 학습 주기 창에서만** 적용
- **모니터링**: svc02 Prometheus 에 postgres_exporter 추가
- **보안**: 사내 DB 정책 준수(계정 분리·접근 통제), 감사로그는 data02 설계에 포함

## 데이터·용량 설계 (유지 — dbqie 산정 수식 그대로 data01/02 에 적용)

- **저장 구성**: 원문 200GB + 벡터 색인 300GB(청크 5,000만×2KB + HNSW×3) + 키워드 색인 200GB
  + 판정 이력 274GB(일 5,000건×50KB×3년) + 체크포인트 450GB(일 1,000세션×5MB×90일)
  + 시계열 요약 500GB = **1,900GB** + WAL·재색인 여유 = **~4TB**
  (data01 30TB 로컬 디스크 內 여유 충분)
- **기준**: 1,000명·전 공정 확산, 이력 3년 보존
- **아키텍처**: WRITERS(ETL·판정기록·체크포인트·시계열 배치) → data01 →
  READERS(Agent 하이브리드 검색·캐시 웜업·학습 추출·감사).
  구성도는 `dbarch.png` 의 dbqie 를 data01 로 치환해 사용

## (보관) 관리형 신청 시 사용했던 산출근거 — 재신청 대비

- vCPU 32: 검색 피크 100QPS × 0.25 core·s = 25 + WAL·재색인 병행 → 32
- MEM 128: 버퍼 32 + 핫캐시 60 + 커넥션 = ~120 → 128
- DISK 4,000: 데이터 1,900GB × 여유 2배 = 3,900 → 4,000
