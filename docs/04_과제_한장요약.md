## 1. 지금 무엇이 문제인가

불량 하나를 판단하려면 SPC 트렌드 · wafer map · 결함 이미지 · Inform Note · 기준정보를 서로 다른 시스템에서 하나씩 열어 대조해야 한다.

| | |
|---|---|
| **시간** | 시스템 사이를 오가며 손으로 대조하는 데 판정 시간의 대부분이 쓰인다. 정작 판단에 쓰는 시간은 그 일부다 |
| **편차** | 같은 현상을 놓고도 사람에 따라 결론이 다르다. 무엇을 봤고 무엇을 안 봤는지가 사람마다 다르다 |
| **공백** | 야간과 주말에는 대응이 다음 근무까지 밀린다. 그 사이 같은 원인의 불량이 계속 생산된다 |
| **휘발** | 왜 그렇게 판단했는지가 사람 머릿속에 남고 쌓이지 않는다. 담당자가 바뀌면 처음부터 다시 푼다 |

기존 대안으로는 안 된다. 사내 LLM API는 사내 DB 조회·이미지 판독을 못 하고 우리 데이터로 정확해지는 경로가 없다. 사내 공용 RAG는 설비 ID 토큰 보호(PHO-D03을 통짜로)와 사내 용어 병기가 안 된다. BI는 볼 화면을 늘릴 뿐이고, SPC 알람은 "이상이다"까지만 말한다.

## 2. 무엇을 만드는가

> **확인 → 판단 → 조치까지 스스로 하되, 모든 판단은 근거를 인용하고 현장 조치는 반드시 사람 승인을 거친다.**

입구는 둘(Chat · 무인 감시), 분석 코어는 하나. Chat에서 검증한 능력이 어댑터 하나로 24시간 감시가 된다.

```
  ┌─ Chat  : 엔지니어가 묻는다 ────────────┐
  └─ 무인  : 감지 이벤트를 질문으로 변환 ──┘
                    │
  adapter → investigator ⇄ tools → judgment → action → answer → register
  증상분류   ReAct 루프로 도구      검증기    등급표    근거     현업 확정
  규칙로드   반복 호출              5칙       + 승인    인용     → 검색 자산
                    │                                              ▲
                    └──── 기간시스템 조회 ────┐    선순환 ─────────┘
                          SPC·MES·YMS·EES·QMS
                          + vision CNN + RAG
```

## 3. 다른 접근과 무엇이 다른가

| | |
|---|---|
| **자동화가 별도 개발이 아니다** | 분석 코어를 Chat과 무인이 공유한다. 파일럿에서 검증한 능력이 어댑터 하나로 24시간 감시가 된다 |
| **수치 환각의 발생원을 없앴다** | 통계·공통성 분석·map 분류·SQL은 전부 코드가 한다. LLM에게는 결과만 넘긴다. 숫자를 지어낼 자리가 구조적으로 없다 |
| **그럴듯한 오답이 채택되지 않는다** | 판단서는 근거 인용을 강제하고 검증기 5칙이 코드로 검사한다. 계속 실패하면 판단 불가로 강등한다 |
| **확산 비용이 구조적으로 낮다** | 공정을 늘릴 때 코어를 다시 만들지 않는다. 조사규칙 문서만 추가하면 된다. 2차년에 이걸 실증하고 확산 표준안으로 산출한다 |

## 4. 틀린 판단이 조치로 이어지지 않게 — 두 겹

**판단 — 검증기 5칙 (코드가 검사)**

| 규칙 | 무엇을 막나 |
|---|---|
| 스키마 | 정해진 형식이 아니면 거부 |
| 근거 실재 | 존재하지 않는 증거를 인용하면 거부 |
| 사실 대조 | 도구가 돌려준 원문에 없는 수치를 쓰면 거부 |
| 신뢰도 규칙 | High를 주장하려면 근거 3개 이상, 반증 0 |
| 공백 금지 | 가설이 없으면 무엇이 부족한지를 명시하게 강제 |

**조치 — 등급표 + 권한별 승인 (LLM이 아니라 규칙표가 정한다)**

| 등급 | 조치 | 1차년 | 2차년 |
|---|---|---|---|
| L0 | 정보 제공 — 분석 답변, 리포트 | 즉시 | 즉시 |
| L1 | 알림 — 담당자 통보, 교대 브리핑 | 즉시 | 즉시 |
| **L2** | **현장 영향 조치 제안 — Lot Hold, dose 보정** | **전건 승인 후 실행** | 전건 승인 후 실행 |
| L3 | 자동 조치 — 되돌릴 수 있는 저위험만 | **개방하지 않음** | 화이트리스트 개별 승격 |

조치 등급을 LLM이 정하지 않는 이유 — 조치는 감사 대상이고, 감사는 설명 가능한 규칙을 요구한다.

## 5. 2개년 단계 계획

### 1차년 (2026-09 ~ 2027-08) — 구축·검증 · 포토 1개 공정

| 분기 | 만드는 것 | 통과 조건 |
|---|---|---|
| 1Q | 조사 코어 골격, 도구 8종, 검증기 5칙, 골든셋 30건 | 골든셋 end-to-end 통과 + 검증기 3종 차단 재현 |
| 2Q | **그림자 운영**, Chat UI, 승인 게이트, 등록 워크플로 | **AI 대 엔지니어 일치율 기준선 실측** (조치 미실행) |
| 3Q | Chat 파일럿 확대, 검색 품질 개선, vision 연결 | 엔지니어가 실제로 쓰는가 · 반려율 · 재사용률 |
| 4Q | Event-to-Question Adapter, 무인 접수, 교대 브리핑 | **무인 2주 연속, 이벤트 처리 누락 0건** |

### 2차년 (2027-09 ~ 2028-08) — 확산·자동화 · 3개 공정

| 분기 | 만드는 것 | 통과 조건 |
|---|---|---|
| 5Q | etch 확산 — 조사규칙·골든셋 추가 | etch 회귀 통과 + **코어 변경 0** |
| 6Q | CMP 확산 + 저위험 자동조치 화이트리스트 | CMP 회귀 통과 + 시나리오별 정확도 실측 근거 |
| 7Q | 자동 실행 감사 대시보드, L3 승격 심의 가동 | **자동 실행 전건 감사, 오판율 측정·공개** |
| 8Q | 선순환 정착, **확산 표준안** 도출 | 3개 공정 동시 회귀 통과 + 표준안 산출 |

**상시 안전망** — 프롬프트·모델·색인을 바꿀 때마다 골든셋 회귀 러너를 돌린다. 통과 못하면 배포하지 않는다.

**왜 이 순서인가** — 신뢰가 없으면 아무도 안 쓴다. 그래서 조치를 실행하지 않는 그림자 운영으로 일치율부터 번다. 조치 사고가 가장 무섭다. 그래서 권한을 위험도 순으로 천천히 연다. 등록이 멈추면 시스템이 죽는다. 그래서 처음부터 등록을 습관으로 만든다.

## 7. 백지에서 시작하지 않는다

| 구분 | 이미 완료한 것 |
|---|---|
| 설계 문서 | 시스템설계서, 상세 구축 로드맵, Tool 카탈로그, 그라운딩 설계, 조사규칙 5종, 구현명세서 등 **31종** |
| 구현 | LangGraph 조사 코어 스켈레톤 실행 확인, 검증기 5칙 구현, prod 백엔드 4종 |
| 평가 | 골든 시나리오 4건 + 회귀 러너 구축, 회귀 검출 동작 확인. 검색 **recall@10 = 0.500 실측** (골든 4건 / 색인 50건) |
| DB | 테스트 VM에 **PostgreSQL 16.14 + pgvector 0.8.1** 구축, 스키마·가드·평가 동작 확인. halfvec 확정 |
| 인프라 | **GPU 수요등록 완료** (H100 20장), BIG VM 5대 산출근거 제출, 스토리지 신청 포함 |

> 설계 · 스켈레톤 · 평가 체계 · DB 까지는 이미 서 있다. 이 과제는 그 위에 실데이터와 실도구를 연결해 두 공정 더 확산하는 단계다. 공모에서 흔히 문제가 되는 "될지 안 될지 모르는 구간"이 이미 지나 있다.

## 8. 착수 전 정리할 것

| # | 항목 | 상태 | 필요한 조치 |
|---|---|---|---|
| 1 | pgvector 버전 | **종료** | 실측 0.8.1 확인 → halfvec 사용 확정 |
| 2 | 모니터링 도구 사내 미러 등록 | 확인 중 | 미등록 시 바이너리 반입 절차 |
| 3 | H100 반입 일정 | 미정 | 과제 마감일과 동기 — 1Q 착수일 결정 요소 |
| 4 | 정보계 접속점 계정·권한 | 미정 | IT 확인 후 조회 전용 계정·뷰 발급 |
| 5 | 고정밀 VLM 이미지 입력 지원 | 확인 중 | 모델 카드 확인 (대안 후보 확보 완료) |
| 6 | 수행 인원 (4개 역할, 연차별) | 미정 | 심사 확정 시 배정 |
| 7 | GPU 제출본 문구 정정 | 신규 | `적재 8장` → `적재 최소 10장` (H100 80GB, 743÷80=9.3) |

4번이 뚫리지 않으면 1Q부터 막힌다. 착수 승인과 동시에 IT 확인을 시작해야 한다.
