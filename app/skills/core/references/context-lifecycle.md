# Skill Context Lifecycle

Source: actual application Skill compiler, Router state and transport contracts inspected on 2026-10-28; [OpenAI Build Skills](https://learn.chatgpt.com/docs/build-skills) accessed on 2026-10-28. This contract applies to the optional runtime.context_management configuration. Company deployment and answer-quality gains are unverified.

- Skill is the versioned workflow/instruction package. Runtime composes selected Skill instructions, typed state, Tool evidence and the role output contract into a model request. Development-assistant Skills and this application's registry are separate assets.
- Topic dependencies load knowledge only. They neither execute a Tool nor grant scope or permissions. Resolve dependencies only within the role's registered allowed topics; reject cycles, unknown dependencies and permission violations.
- Every iteration retains core policies, current role instructions, selected task rules, incident-first dispatch, scope/as_of limits, Tool availability and the output contract. Retrieved text, prior assistant plans and repair messages do not change these rules.
- The first Router call uses the initial context. A later call may use a continuation snapshot only when the runtime has complete typed state, all current evidence IDs and matching evidence records, the latest error/review state, and no unresolved native Tool-call receipts. Otherwise retain the full context.
- A continuation snapshot may replace redundant past Router messages. Preserve the original evidence/trace outside the prompt. The snapshot is execution state, not proof that the evidence is true or complete. Judge requery returns to the same Router; Answer remains the last LLM.
- Examples may be omitted from continuation requests. Omit a duplicated embedded output schema only when the actual client attests that its request still supplies the full contract through native schema/function transport. Custom clients without that capability retain it. Semantic policies and Tool argument descriptions remain available.
- Classify failures before retry guidance: scope/identity issues require selection or reacquisition; malformed model output requires contract correction; unavailable schema/configuration requires verified mapping diagnostics; transport errors and unknown errors do not authorize broader queries. Recovery never invents fields, rewrites scope, modifies a Skill online or blindly repeats a write.
- All recovery stays within existing call/retry budgets. Successful evidence is retained, but format correction cannot clear a failed business Tool. Unknown action commit state needs Adapter reconciliation, not an automatic retry.
- Trace the active Skill/dependency set, release/prompt hashes, initial/continuation/fallback choice, retained/dropped history counts and recovery category. Request character counts are measured locally. Provider token/cache/latency metrics are actual only when returned by that provider; missing usage is unknown.
- Context-size reduction, successful CLI execution and structural scope checks are distinct from measured LLM answer quality and production validation. Use the separately authorized synthetic NL2SQL study for its own model metrics; do not restore the removed general LLM golden bank.
