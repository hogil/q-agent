# Answer 조건 예시

아래 문장은 주어진 가상 근거에 대한 표현 예시다. 실제 호출에서 수치/ID를 복사하지 않는다.

independent 요청에서는 '사고 테이블을 조회하지 못했습니다' 같은 불필요한 제한 대신 요청한 개념/문서 내용을 답한다. 사고가 없다고 주장하지 않는다.

| 입력 근거 | 표현 |
|---|---|
| DB 5 Lot/60 Wafer, 모든 페이지 조회, source_completeness=unknown | '현재 DB에서 조회된 목록은 5 Lot, 60 Wafer입니다. 사고 테이블의 등록 누락 여부는 확인되지 않았습니다.' |
| 7/60 Wafer만 확보하고 추가 조회 불가 | '현재 7개 Wafer만 조회됐습니다. 전체 60개 중 나머지 목록은 확보하지 못했습니다.' |
| 검증된 배열 집계: 전체 1건, D1a 1건, D1z 1건 | '한 사고가 두 세대에 포함됩니다. 세대별 합계 2건은 전체 고유 사고 수가 아닙니다.' |
| 사고 테이블에는 외곽 Focus 변화 관측, 확정 원인 근거 없음 | '외곽 Focus 변화가 관찰됐습니다. 원인으로 확정할 근거는 부족합니다.' |
| 과거 문서에 보정 원복 조치, 현재 적용 확인 없음 | '과거 사고에서는 보정값 원복을 적용했습니다. 현재 제품/Layer 적용 여부는 추가 확인이 필요합니다.' |
| Hybrid 후보 10개를 확인했음 | '검색된 후보 10개를 확인했습니다.' 전사 관련 사고가 총 10건이라고 쓰지 않음. |
| DB 연결 실패 | '사고 DB 조회에 실패해 결과를 확인하지 못했습니다.' 사고 없음으로 쓰지 않음. |
| '외곽 패턴이면 설비 원인 맞지?'에 유사 이미지 근거만 있음 | '외곽 패턴의 유사성은 확인됐지만 설비 원인으로 확정할 근거는 없습니다.' 사용자의 확신을 따라가지 않음. |
| 질문은 건수만, 조회 근거는 고유 사고 3건 | '적용한 조건에서 고유 사고 3건이 조회됐습니다.' 범위/기준시점은 입력에 있는 값만 덧붙이고 불필요한 원인 분석은 생략. |
| 부분 조회인데 본문은 '전체 확인 완료', limitations에만 누락 표시 | 부적합. 본문에도 확인한 범위와 누락을 명시하고 partial로 반환. |
| 과거 개선 조치 기록만 있고 현재 실행 결과 없음 | 기록된 조치로 설명한다. '제가 수정했습니다', '조치 완료'라고 쓰지 않는다. |
| 점검 계획 요청, 과거 CD/Overlay 참조와 Recipe 변경 있음 | '대상: 변경 전후의 동일 Step 계측 / 이유: 과거 참조와 같은 계측 항목 / 비교: 동일 조건 CD 및 Overlay Raw/Fit/Res. 미실행 점검 권고입니다.' 실제 근거에 있는 대상만 사용. |
| 현재 EDS 미연결, 과거 Yield/Bin은 존재 | '현재 EDS는 확인 대기. 대상 Fab 쌍의 Yield·Bin·Fail 위치를 수신 후 같은 제품/검사 조건의 비교군과 대조. Bin 정의·좌표 정렬도 확인.' 과거 수치는 별도 표기하며 현재 결과로 쓰지 않음. |
| 현재 DOWN/PM 이력과 과거 CD/SEM 참조만 조회됨 | '현재 DOWN 구간의 센서·보정 로그를 점검'은 가능. '과거에도 동일한 DOWN/PM 로그가 있었다'는 불가. 과거 설비 로그는 조회되지 않았다. |
| 과거 참조의 Step/Item/설비만 일치하고 Recipe·제품·검사 조건은 없음 | 확인된 세 조건만 매칭 근거다. 나머지는 비교 전에 확인할 조건이며 이미 동일하다고 쓰지 않는다. |
