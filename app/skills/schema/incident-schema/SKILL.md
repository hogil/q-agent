references/logical-schema.json에서 질문에 필요한 논리 필드와 관계를 사용한다. 실제 이름은 관리자가 설정한 mapping 파일을 Adapter만 읽는다.
현재 통합 설정의 tables.<entity>.columns와 relations가 물리 매핑 원본이다. 경로나 모델 파일명 변경은 배포 설정에서 처리하며 역할 프롬프트에 복사하지 않는다.
incident_id는 내부 고유키, incident_number는 표시번호다. 둘이 같다고 가정하지 않는다. 발생 부서/개선 부서, 발생일/등록일/FAB Out 시점도 구분한다.
도시는 위치이고 line은 라인이다. 제품세대 원본은 기존 array 컬럼이다. {D1a,D1z,D20,FET,V5,V6,V7,V8} 같은 다중값을 그대로 유지한다. 검색은 원소 정확 일치, 통계는 조회 시 배열을 펼친 뒤 내부 사고 ID 중복 제거로 처리한다. 별도 연결 테이블로 원본 이전을 요구하지 않는다. 세대별 수량/불량 매핑은 배열만으로 추정하지 않는다.
물리 스키마 변경은 필드명만 바꾸면 되는지 또는 관계/타입/코드 의미가 변한 것인지 구분한다. 의미 변경은 Catalog와 회귀 사례도 함께 수정한다.

## 통계

집계는 aggregate_incidents 등 검증된 코드/SQL로 수행한다. 전체 조회 모집단과 상위 N개 표시를 구분한다.
고유 사고는 distinct incident_id, 사고별 Lot 관계는 incident_id+lot_key, 고유 Lot는 검증된 lot_key 기준이다.
다중세대 포함 사고 합계는 고유 사고보다 클 수 있다. 영향 수량은 실제 배분 값만 사용한다. 모르는 수량은 0이나 균등 배분으로 바꾸지 않는다.
불량률은 같은 대상·기간·단위의 분모가 필요하다. FAB Out 분류 미등록은 정상 판정이 아니다.
DB 내부 집계와 문서 일부의 수치를 합치지 않는다. 데이터 완전성, 기준시각, 필터와 단위를 함께 반환한다.

## 실제 데이터 확인 후 변경

수정 전 관련 실제 원본과 대표 데이터를 확인하고 출처, 기준시점, 변경 근거를 기록한다. 실제 데이터에 접근할 수 없으면 미확인으로 표시하고 설계/더미 초안으로만 관리한다. 더미 검증을 실제 데이터 검증으로 주장하거나 확인 없이 컬럼 의미, 관계, 코드값을 확정하지 않는다. 이 규칙은 원본 데이터 수정이나 온라인 Skill 자기 수정 권한을 부여하지 않는다.
